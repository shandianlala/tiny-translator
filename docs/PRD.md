# PRD: Tiny Translator — 精简划词查词 Chrome 插件

## Problem Statement

我在浏览英文网页时经常遇到不认识的单词。现有的翻译插件要么功能臃肿（整页翻译、句子翻译、生词本复习、账号同步），要么查一个词要跳出页面。我只想要三样信息——音标、中文释义、这个词最常用的几个搭配短语——并且能把查过的词随手存下来以后翻看。市面上没有一个"特别精简"、只做这一件事的工具。

## Solution

一个自用的 Chrome 插件（Manifest V3，开发者模式加载）：在任意网页选中一个英文单词，选区右下角浮现一个小角标；点击角标弹出查词卡片，展示美/英音标（点击可发音）、按词性的中文释义、词典返回的前 3 个常用词组（带中文）；卡片上一键收藏，收藏快照存在本机；点击浏览器工具栏图标即可查看、删除、导出全部收藏。

两步触发（先角标、后卡片）避免误弹；仅对"单个纯英文单词"的选区响应，其余选区完全无感。

## User Stories

1. 作为插件使用者，我想在网页上选中一个英文单词后看到一个不打扰的小角标，以便自主决定是否查词而不被误弹的窗口干扰。
2. 作为插件使用者，我想点击角标后立刻在原地看到查词卡片，以便不离开当前阅读上下文。
3. 作为插件使用者，我想在卡片上看到单词的美式音标和英式音标，以便确认这个词的正确读法。
4. 作为插件使用者，我想点击音标就能听到对应口音的真人发音，以便核对我心里的读音。
5. 作为插件使用者，我想看到按词性分行的中文释义，以便快速判断这个词在当前句子里的含义。
6. 作为插件使用者，我想看到该词最常用的前 3 个搭配词组及其中文意思，以便学到这个词的实际用法而不只是孤立释义。
7. 作为插件使用者，我想在卡片上点一下星标就完成收藏，以便不打断阅读节奏。
8. 作为插件使用者，我想在打开卡片时就看到这个词是否已被收藏（星标点亮），以便不重复操作。
9. 作为插件使用者，我想重复收藏同一个词时自动覆盖旧记录而不产生重复条目，以便收藏列表保持干净。
10. 作为插件使用者，我想点击浏览器工具栏图标就看到全部收藏的单词列表（按收藏时间倒序），以便随时复看查过的词。
11. 作为插件使用者，我想在收藏列表里直接看到每个词的音标和释义摘要，以便不用逐个点开。
12. 作为插件使用者，我想点击列表中的单词展开它的收藏时词组快照，以便离线回顾完整的查词结果。
13. 作为插件使用者，我想在收藏列表里删除不再需要的词，以便列表只保留我还没记住的词。
14. 作为插件使用者，我想一键把全部收藏导出为 JSON 文件，以便备份或迁移到别的电脑。
15. 作为插件使用者，我想在断网时依然能查看收藏列表的全部内容（含音标、释义、词组），以便收藏不依赖数据源存活。
16. 作为插件使用者，我选中短语、句子、中文或数字时不希望出现任何角标，以便插件在不相关的场景下彻底隐身。
17. 作为插件使用者，我想在查询失败（查不到词/网络异常）时在卡片内看到一行简短提示，以便知道发生了什么而不是面对空白。
18. 作为插件使用者，我想通过点击页面其他位置或按 Esc 关闭角标和卡片，以便快速回到阅读。
19. 作为插件使用者，我想让插件的界面样式不被所在网页的 CSS 污染、也不污染网页，以便在任何网站上卡片外观一致。
20. 作为插件使用者，我希望插件只在查词时向数据源发送被查的那个单词、不上传浏览记录或页面内容，以便隐私可控。
21. 作为插件使用者，我希望插件零依赖、无构建步骤，克隆目录后用开发者模式直接加载即可使用，以便维护成本最低。
22. 作为插件维护者，我希望数据源接口的请求和解析集中在单一模块，以便非官方接口失效时只改一处就能整体换源。

## Implementation Decisions

- **架构**：Manifest V3，三个运行环境各司其职——content script 负责划词检测与全部页面 UI；background service worker 负责跨域请求数据源并解析；action popup 负责收藏的浏览与管理。权限最小化：仅 `storage` 权限 + 有道域名的 host 权限。
- **数据源**：有道非官方 jsonapi（一次请求同时返回音标、按词性中文释义、词组列表）；发音走有道 dictvoice 接口（type=2 美音 / type=1 英音）。自用场景接受非官方接口的失效风险，解析逻辑集中在 background 单一模块以便换源。
- **"前 3 个高频短语"的定义**：已确认降级为"词典返回顺序的前 3 个词组"，不引入词频语料重排。
- **触发规则**：选区 trim 后必须匹配"1–45 个纯英文字母"才出角标；两步交互（角标 → 卡片）防误触；点击页面空白或 Esc 关闭。
- **消息契约**：content script 向 background 发送 `{type:'lookup', word}`，background 回 `{ok:true, result}` 或 `{ok:false, error:'notfound'|'network'}`。
- **查词结果结构**（由原型对真实接口响应验证后固化）：

  ```
  { word, usPhone, ukPhone, defs: string[], phrases: [{ text, trans }] }
  ```

  接口响应中无英汉词典字段或释义为空 → 视为 notfound；音标或词组缺失时对应区域不渲染，不视为失败。
- **收藏存储**：`chrome.storage.local`，结构为以小写单词为 key 的对象 map `{ favorites: { [word]: 查词结果快照 + savedAt } }`——map 结构天然实现"重复收藏即覆盖"。收藏存完整快照，保证离线可看。
- **导出**：popup 内按钮将 favorites 序列化为 JSON 文件下载，作为备份/迁移手段（storage.sync 因 100KB 配额被否决）。
- **UI 隔离**：页面内角标与卡片挂载在 closed Shadow DOM 中，与页面样式双向隔离。
- **技术栈**：原生 JavaScript，无框架、无构建步骤、零运行时依赖。

## Testing Decisions

- **好测试的标准**：只断言外部行为——给定一份数据源接口的原始 JSON 响应，断言解析产出的查词结果结构（音标值、释义条数与内容、词组截断为 3 条、缺字段时返回 null）；不断言解析函数内部如何遍历字段。
- **唯一测试接缝**：background 模块中的接口解析纯函数 `parseResult`（已与用户确认）。它是插件唯一的数据加工点，不依赖网络与 Chrome API，用真实接口响应做 fixture 即可覆盖核心正确性。
- **fixture 来源**：开发期间已 curl 抓取真实接口响应（`example` 一词）并跑通验证，该样本应固化为测试 fixture；补充一个"查不到词"的空响应 fixture。
- **测试运行器**：node 内置 `node:test`，保持零依赖。
- **prior art**：本仓库尚无既有测试；开发过程中用 node 脚本对真实响应做过一次性验证，测试即该验证的固化。
- **不进自动化范围**：划词/角标/卡片的 DOM 交互、发音播放、popup 界面——靠真机手动验证（验证清单见 Plan 文档）。

## Out of Scope

- 短语、句子、整页翻译（仅单个英文单词）。
- 生词本复习/记忆曲线等学习功能。
- 多设备同步（storage.sync 已评估并否决）。
- 基于词频语料的短语真实高频排序。
- 设置页/选项页。
- 发布到 Chrome Web Store（自用，开发者模式加载）。
- 键盘划词（Shift+方向键选词）触发角标。
- 输入框（input/textarea）内选词。

## Further Notes

- **已知局限**：`chrome://` 页面与 Chrome 内置 PDF 阅读器无法注入 content script（浏览器限制）；严格 CSP 的站点上发音音频可能被拦截（音频元素在页面上下文创建）。
- **非官方接口风险**：数据源无 SLA，可能限流或改版；解析已隔离在单一模块，换源成本被刻意压到最低。
- 实现已完成（2026-07-07），本 PRD 为事后固化的需求与决策记录；`ready-for-agent` 的待办仅剩 Testing Decisions 中的 parseResult fixture 测试。
