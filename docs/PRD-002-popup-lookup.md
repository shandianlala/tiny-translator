# PRD: popup 主动查词 — 输入框查单词

## Problem Statement

现在查词只有一条路径：单词必须出现在网页上并被我选中。当我脑子里想到一个词、或从视频/纸书/聊天里看到一个词时，插件帮不上忙——我得先找个地方把词打出来再选中它，或者退回去用别的词典工具。查词入口不该依赖"词恰好在网页上"。

## Solution

在工具栏 popup 顶部增加一个输入框（打开即聚焦）和右侧的小"译"按钮。输入单词后按回车或点按钮，输入框下方出现结果区，内容与划词卡片完全一致：美/英音标（点击发音）、按词性中文释义、前 3 个常用词组、★ 收藏。收藏列表顺势下移，不切换视图；收藏后列表立即刷新。划词和手动输入两条入口共享同一套查词与收藏行为。

## User Stories

1. 作为插件使用者，我想在 popup 里直接输入一个英文单词查询，以便查词不依赖单词恰好出现在当前网页上。
2. 作为插件使用者，我想打开 popup 时输入框自动聚焦，以便打开后直接打字、零多余点击。
3. 作为插件使用者，我想按回车立即触发查询，以便手不离键盘完成整个查词动作。
4. 作为插件使用者，我想输入框右侧有一个小翻译按钮，以便习惯鼠标操作时也能触发查询。
5. 作为插件使用者，我想在结果区看到与划词卡片完全一致的内容（美/英音标、按词性中文释义、前 3 词组），以便两个入口的体验没有认知差异。
6. 作为插件使用者，我想点击结果区的音标听到对应口音的发音，以便核对读音。
7. 作为插件使用者，我想在结果区点 ★ 收藏这个词，以便手动查的词和划词查的词进入同一个收藏列表。
8. 作为插件使用者，我想查询已收藏过的词时看到 ★ 已点亮，以便知道自己收藏过它。
9. 作为插件使用者，我想收藏后下方的收藏列表立即刷新出现该词，以便得到明确的操作反馈。
10. 作为插件使用者，我想查询结果显示时收藏列表仍然可见（顺势下移），以便查词和翻收藏互不打断。
11. 作为插件使用者，我输入不合规内容（短语、中文、数字、超长字符串）时想在结果区看到"仅支持单个英文单词"的提示且不发出请求，以便立刻明白这个入口的能力边界。
12. 作为插件使用者，我想在查不到词或网络失败时在结果区看到一行简短提示（与划词卡片文案一致），以便知道发生了什么。
13. 作为插件使用者，我希望这个新入口不引入任何新权限、不增加插件体积负担，以便插件保持"特别精简"的定位。
14. 作为插件维护者，我希望手动查词完全复用既有的查词消息契约和解析模块，以便数据源换源时两个入口同时生效、只改一处。
15. 作为插件维护者，我希望"单个英文单词"的校验规则成为共享纯模块里的具名函数并被测试锁定，以便划词与手动输入两个入口的触发规则不悄悄漂移。

## Implementation Decisions

- **改动范围**：仅 popup 层（页面结构 + 脚本）与共享纯模块；background、content script、manifest 均不动。低于 Plan Required 三文件门槛，不另开 Plan 文档。
- **查词链路**：popup 作为既有 `{type:'lookup', word}` 消息契约的第二个消费者，向 background 发同一消息，接同一 `{ok, result}` / `{ok:false, error:'notfound'|'network'}` 响应。数据源与解析零改动。
- **校验规则共享**：将"单个纯英文单词（1–45 个字母）"校验从划词侧的内联正则提升为共享纯模块中的 `isTranslatableWord(text)` 纯函数；popup 以 module script 方式引用。content script 因无法 import（不上构建步骤），保留一份等价正则副本，一致性由共享模块的测试锁定。
- **触发方式**：回车或点击输入框右侧"译"按钮；不做输入防抖实时查询（非官方接口经不起频繁请求，且需处理请求竞态）。
- **不合规输入**：校验不通过时在结果区显示提示，不发请求。
- **结果区**：位于输入框与收藏列表之间；音标点击发音（popup 环境无页面 CSP 干扰，比划词卡片更可靠）；★ 收藏走既有 storage upsert（小写词为 key，天然覆盖去重），收藏后立即重渲染收藏列表。
- **视图关系**：结果区插入式展示，收藏列表下移，无视图切换状态机。

## Testing Decisions

- **好测试的标准**：只断言外部行为——给定输入字符串，断言 `isTranslatableWord` 的布尔结果；不断言正则写法等内部实现。
- **测试接缝（已与用户确认）**：不新增接缝。`isTranslatableWord` 并入既有共享纯模块，测试加在既有测试文件中；查词解析已被 `parseResult` 的 5 个 fixture 测试覆盖，本功能不重复测。全仓库测试接缝维持一个。
- **用例范围**：合法单词（含 1 字母词、45 字母边界）、空串、多词短语、含数字/标点/中文、首尾空格容忍、超长串。
- **prior art**：既有 `node:test` + fixture 测试（parseResult），同文件同风格延续。
- **不进自动化范围**：popup 的 DOM 交互（聚焦、回车、按钮、结果渲染、列表刷新、发音）——真机手动验证。

## Out of Scope

- 边输边查（防抖实时查询）。
- 查词历史记录。
- popup 内查短语/句子等非单词文本。
- 网页内快捷键唤出输入浮层。
- content script 侧的模块化改造（为消除正则副本上构建步骤）。
